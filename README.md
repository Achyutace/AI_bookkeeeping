齐乐辰的记账系统。
- 微信
- 支付宝
- 农业银行银行卡
- 招商银行银行卡
其中农行的卡和招行的卡可能和微信支付有重叠；支付宝会有利润忽略。
类型主要有高铁/飞机票，各种吃饭，

用户旅程地图：
0. 可以开平帐模式，也就是自动平“微信”
1. 让我可以标注这笔钱干了什么
2. 自动给我分类什么类别用了多少钱
3. 标注哪天花了多少
4. 可以管理categroy。

## 技术栈：
前后端都是js，用Vue3。backend分route、service、repositories、utils四个文件夹，frontend/src分views，components，api三个文件夹
数据直接用csv管理，我直接直接开一个/data文件夹。


## 数据库设计
category.json:类和标签的对应关系
account.json: 有什么账户

然后每个支出条目的key有：
- id: 主键，从1顺着排
- date
- time(非必填)
- category
- tag（非必填）
- amount（正表示支出，负表示收入）
- account（微信、支付宝、银行卡）
- status（0表示正常，具体数字表示退款，比如薯岛退10%的金额就是59.9和-5.99）

- note（非必填）

## 前端功能设计
顶栏横栏的按钮分两个：数据看表和日历看表。右上角是导入和个人资料。下面是筛选按钮和看板
### 数据看表
- AI对话聚类接口：输出一个列表，展示所有列表里的id。按理来水
- AI打标：前端有个按钮，让AI一键达标。
- 上面可以进行数据筛选，筛选日期、分类、标签。包含部分退款的条目显示xxx（已退款）
- 下面是一条条的数据看板，预览每个支出条目，涵盖所有的key
#### 自动去重
- 场景：
    - 我微信有的时候会刷农行的卡，此时微信和农行就会同时有这比开销
    - 我可能同时导入2026.06-08和2027.07-09的微信账单，此时就需要自动去重

### 日历看表
- 初始状态上面是大概16:9的日历看板，下面是空白区域用于显示详细信息
- 可以查看每天、选定条目内的收入或支出
- 点击某一天，下面会显示这一天的看板，可以按照分类预览饼形图、条形图，也可以查看条目（就做成数据看表的component）
