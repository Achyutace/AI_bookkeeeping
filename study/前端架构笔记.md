## 1. 数据模型（写代码前先背下来）

### Entry —— 一条账

| key | 类型 | 说明 |
|---|---|---|
| `id` | number | 主键，从 1 顺延 |
| `date` | string | `"2026-09-01"` |
| `time` | string | 非必填，`"19:19:08"` |
| `category` | string | 一级类目，如 `"餐饮"` |
| `tag` | string | 非必填，二级标签，如 `"外卖"` |
| `amount` | number | **正数 = 支出，负数 = 收入**（显示和数据统计都要靠这条） |
| `account` | string | 微信 / 支付宝 / 农行 / 招行 |
| `status` | number | `0` = 正常；非 0 表示部分退款（如薯岛退 10%：`59.9` 配 `-5.99`） |
| `note` | string | 非必填 |

### Category —— `data/齐乐辰/category.json`

```json
{
  "支出": { "餐饮": ["外卖", "水果"], "交通": ["打车", "火车"] },
  "收入": { "家长给钱": [], "实习": [] }
}
```

- 顶层只有 `支出` / `收入` 两个 key。
- 值是对象：**key = 一级类目**，**value = 该类的标签数组**（可为空 `[]`，表示这类还没标签）。
- 存在**全局 tag**（如 `"大钱"`），不挂任何类目。后端返回时放在 `general_tag` 里。
- `大钱` 是特殊标签：可以支持「隐藏大开销」看日常花了多少。

### Account —— `data/account.json`

```json
{ "齐乐辰": { "微信": {...}, "支付宝": {...}, "农行": {...}, "招行": {...} } }
```
- 顶层 key 是**用户名**，值是该用户下的账户。目前只有一个用户「齐乐辰」。
- 农行/招行可能和微信有**重叠账单**（微信刷农行卡），所以有「自动去重」需求。

### ⚠️ 待确认（写 `EntryList` 之前必须解决）

`GET /api/entries` 到底返回**完整条目数组**还是**id 列表**？
`backend.md` 里 description 写 "get all entries"，return 又写 "所有待选的 id"，两句矛盾。
→ 这决定表格能不能靠一个接口渲染。**先问自己的后端（或先自己定一个，后端跟着改）。**

## 2. 目录结构与文件职责

```
frontend/
├─ index.html              # 唯一入口 html，里面有 <div id="app">
├─ package.json            # 依赖和脚本
├─ vite.config.js          # 构建配置；要加 /api 代理到后端
└─ src/
   ├─ main.js              # ①②③：创建 app、装 router/pinia、挂载
   ├─ App.vue              # 相框：顶栏 + <router-view>，不装具体内容
   ├─ style.css            # 全局样式
   ├─ router/index.js      # 路由表：路径 → 哪个 view
   ├─ api/
   │  ├─ http.js           # fetch 封装：baseURL、JSON、统一报错
   │  ├─ entries.js        # 所有 /api/entries 的调用
   │  ├─ category.js       # 所有 /api/category 的调用
   │  └─ user.js           # 所有 /api/user 的调用
   ├─ stores/
   │  ├─ entries.js        # entries 列表 + 筛选条件 + loading
   │  ├─ category.js       # 分类数据（筛选栏要用）
   │  └─ user.js           # 当前账目
   ├─ views/               # 页面级：负责「组装」
   │  ├─ TableView.vue     # 数据看表
   │  ├─ CalendarView.vue  # 日历看表
   │  └─ ProfileView.vue   # 个人资料
   ├─ components/          # 零件级：只管自己的事
   │  ├─ TopBar.vue
   │  ├─ FilterBar.vue
   │  ├─ StatsPanel.vue
   │  ├─ EntryList.vue     # el-table 封装，日历页复用
   │  └─ charts/           # PieChart.vue / BarChart.vue
   └─ utils/
      ├─ format.js         # 金额/日期格式化、正负染色
      └─ constants.js      # account 列表、status 含义等常量
```

**一句话区分 view 和 component：**
- `views/` = 页面，一个路由一个，负责**把零件拼起来** + **从 store 取数据**。
- `components/` = 零件，**不知道数据从哪来**，靠 `props` 拿、`emit` 往外送。所以才能被日历页复用。

## 4. Vue 核心概念速查

### 响应式：数据变了，界面自动变
```js
import { ref, computed } from 'vue'

const count = ref(0)        // 基础类型用 ref，读写要 .value（模板里不用写 .value）
const list  = ref([])
const total = computed(() => list.value.reduce((s, x) => s + x.amount, 0))  // 派生值
```
> `reactive` 用于对象，但**新手统一用 `ref` 更不容易踩坑**。

### 父子通信：props 向下，emit 向上
```js
// 父 App.vue
<EntryItem :entry="e" @delete="onDelete" />

// 子 EntryItem.vue
const props = defineProps({ entry: Object })   // 接收
const emit  = defineEmits(['delete'])          // 声明能发什么
emit('delete', props.entry.id)                 // 往外送
```
**铁律：子组件永远不要直接改 props。要改，就 emit 让父组件改。**

### 生命周期
```js
import { onMounted } from 'vue'
onMounted(() => { fetchEntries() })   // 组件挂载后跑一次，拉数据放这
```

### 模板语法
```
v-if="loading"       条件渲染
v-for="e in entries" 循环（记得 :key="e.id"）
v-model="keyword"    双向绑定（输入框）
:prop="value"        : 是绑定表达式，不加 : 就是纯字符串
@click="fn"          @ 是监听事件
```

### Pinia store 三段式
```js
import { defineStore } from 'pinia'
import { ref } from 'vue'

export const useEntriesStore = defineStore('entries', () => {
  const entries = ref([])            // state
  const loading = ref(false)
  const fetch = async () => { ... }  // action
  return { entries, loading, fetch } // 必须 return 出去
})
```
组件里用：`const store = useEntriesStore()`，然后 `store.entries`、`store.fetch()`。

## 5. 对接后端的接口清单（来自 backend.md）

| 用途 | Method + Path |
|---|---|
| 取条目 | `GET /api/entries` |
| 改单条 | `PATCH /api/entries/:id` |
| 删单条 | `DELETE /api/entries/:id` |
| 批量新增 | `POST /api/entries/batch` |
| 批量改 | `PATCH /api/entries/batch` |
| 批量删 | `DELETE /api/entries/batch` |
| 看分类 | `GET /api/category` |
| 加分类 | `PUT /api/category` |
| 删分类 | `DELETE /api/category` |
| 新建账目 | `PUT /api/user` |
| 删账目 | `DELETE /api/user` |

**Vite 代理**（`vite.config.js`）——前端 5173 端口直接打会给跨域拦，要代理到后端：
```js
server: { proxy: { '/api': 'http://localhost:后端端口' } }
```
